# Local architecture

YureAtlas is a modular monolith with four Compose services:

- **web**: Next.js App Router/React/TypeScript, Tailwind, Lucide, MapLibre and Recharts. A server-only `/api` proxy preserves the browser's same-origin boundary; API configuration is not exposed through public environment variables. The basemap is bundled Natural Earth GeoJSON. No external tile/font/CDN requests are needed at runtime.
- **api**: FastAPI/Pydantic and SQLAlchemy with a bounded pool. Reads return immutable archive data; long mutations enqueue jobs and return HTTP 202. Readiness checks the migrated database and artifact directory. Only explicitly allowed origins/hosts and a custom request header permit mutations. Services bind to loopback on the host.
- **worker**: the same Python image/package, PostgreSQL durable queue, an installation-wide advisory lock and monotonic schedule reconciliation. Each claim has a new attempt token tied to the registered worker session. Jobs use unique logical keys, `FOR UPDATE SKIP LOCKED`, two-minute leases measured by the database clock, 15-second heartbeats and at most three total attempts. Domain transactions verify the current worker and attempt before committing. Network requests have bounded backoff; publication has its own unique logical key.
- **db**: PostgreSQL 17.9 with PostGIS 3.6.4 installed in a Debian-based multiarch image, tested on Apple Silicon. The published base tags and lockfiles are pinned; rebuilding the DB image may pick up patched transitive Debian packages. Use tested image digests for stricter bit-level environment retention.

## Storage and transactions

Relational entities include sources, ingestion reports, stable event identities, append-only revisions, snapshots, versioned experiments and grids, feature sets, models, forecasts/cells, evaluations/cells, durable jobs, promotion audit records, append-only schedule configurations, a scheduling decision cursor, runtime application acknowledgment, and worker heartbeat. JSONB holds structured configuration/diagnostics, not the whole application. Time/source/foreign-key paths have B-tree indexes; PostGIS geometries have GiST indexes. Every timestamp is timestamptz. Forecast-cell uniqueness and finite probability bounds are database constraints.

Immutable tables reject update/delete. Child forecast/evaluation rows are inserted before their run using deferred foreign keys; the publication trigger checks complete grid membership, and the sealing trigger rejects new child rows once the parent exists. An API/UI restriction alone is not the protection. A database owner can still deliberately change schema/triggers; these controls protect normal application transactions, not a hostile local administrator.

Artifacts use immutable SHA-256 filenames under the persistent artifact volume. Raw payloads, feature Parquet batches, model joblib files, dependency manifests and reports are atomically written, fsynced, and verified on reuse. Orphan artifacts after a failed database transaction are harmless and retained; no automatic garbage collector removes research history. Only locally produced, DB-referenced model files are deserialized.

The worker's singleton connection is idle in autocommit mode during computation and network requests. Registration records its token, backend PID, backend start time, and scheduling environment setting. Before a scoped transaction commits, it locks and verifies the registered worker row and, for job execution, the current job attempt, cancellation flag and lease. Control operations needing both rows take worker then job locks and do not acquire domain locks afterward; cancellation locks only the job. Claims first acquire the schedule advisory lock, shared with configuration changes and planning, before taking worker/job locks. A successor registers through the same worker row, so it cannot acknowledge takeover while an earlier authorized publication is committing. Cancellation similarly serializes through the job row. Losing a socket is not an instantaneous rollback of an already authorized commit; after takeover or cancellation is acknowledged, earlier execution cannot commit new domain/archive changes. Content-addressed orphan files and earlier committed ingestion batches are retained.

## Data flow

1. A validated request enqueues a unique job. Forecast jobs preserve the original payload, pin their target at request time and resolve model-selection provenance once before publication. Retries use that saved identity. The API never performs training or simulation in an in-process background task.
2. Worker retrieval stores raw source artifacts, normalized append-only revisions, rejection reports, and explicit coverage intervals. Receipt time differs from origin/provider update time.
3. Fitting creates an exact revision snapshot, temporal feature batches and manifest, then model versions with diagnostics and availability.
4. Prediction checks experiment compatibility, cutoffs, model availability, source freshness and complete output. Atomic publication records issue time, 24-hour window, frozen probabilities/colours, code version and dependency manifest.
5. Evaluation requires completed covered target windows, reconstructs a frozen observation snapshot, scores saved probabilities, and appends a new version only when observations/coverage change.
6. The dashboard fetches per-cell GeoJSON and source-compatible event overlays, exposes job progress, and compares matching forecast/observation pairs.

## Scheduling and recovery

The fixed JST cadence is recent ingestion every 15 minutes, following-day forecast at 23:40 (23:30 input cutoff), evaluation at 06:00, 31-day reconciliation at 06:30 (including D+3/7/30), and candidate retraining Sundays at 03:00. A 30-second monotonic timer reconciles durable decisions on startup and during operation, independently of worker heartbeat. Jobs, the decision cursor, and successful runtime acknowledgment commit atomically. Restart from 23:40 until midnight queues the still-eligible upcoming target once; absent expired targets become missed jobs within a 31-target-per-experiment recovery bound. Existing decisions remain unchanged. Safe work coalesces to its latest due occurrence. Composite USGS reconciliation refreshes then evaluates even if the standalone ingestion/evaluation kinds are disabled; JMA reconciliation evaluates imported evidence. Weekly training pins its requested endpoint and never promotes automatically.

`PUT /schedules` appends an audited configuration using an expected-revision compare-and-swap and reason; stale saves return 409. Scope is all real experiments or at most 100 selected real IDs, with switches for the five job kinds. Empty scope/kinds produce no work. All-real scope exceeding 100 blocks planning and automatic claims; settings remain editable so the scope can be narrowed or scheduling disabled. The worker's `SCHEDULE_ENABLED=false` overrides persisted enablement. A process-enabled timer continues polling a persisted disable, recording successful application without advancing the decision cursor. A changed active specification hash restarts bounded catch-up; a reason-only revision does not. Queued automatic work is paused by the effective scope/kinds/enablement, while manual jobs remain usable and running attempts continue until completion or explicit cancellation. Cancelled or exhausted queued/expired entries may still receive terminal cleanup without redispatch.

`GET /schedules` separates the requested revision, actual registered worker process setting, and last committed application. Missing/stale worker evidence cannot establish current application; API environment values alone do not establish worker behavior. Strictly future regular occurrences are distinct from the bounded next-check estimate and current eligible forecast target; neither promises dispatch or publication. Promotion history and model-selection preview endpoints expose the actual selection policy and archived metadata. Promotions reject synthetic models, apply to future unresolved selections, and preserve issued forecasts and already-resolved jobs. The preview does not reserve a model or verify artifact bytes and catalogue coverage. [Scheduling policy](scheduling.md) details API limits, canonical keys, application state, clock changes, and omitted-history diagnostics. Schedules run only while the worker and computer run. Cancellation is cooperative at batch/simulation checkpoints; individual model fitting calls finish their bounded operation before cancellation is observed.

## Backup and restore

The backup command stops API and worker writes, captures `pg_dump` plus all verified artifact bytes, writes a checksum manifest, then resumes previously running writers. Restore verifies the manifest and every artifact path/content hash, then restores into a **new Compose project and new volumes**, leaving the original installation untouched. Default restore ports are 3001/8001/55433. Schedules remain disabled in the restored installation until explicitly enabled. No uploaded ZIP/tar member is extracted to an arbitrary filesystem path.

## API contract

`docs/openapi.json` is generated from the application; `apps/web/lib/schema.d.ts` is generated with openapi-typescript and consumed by the frontend. `/health`, `/ready`, `/experiments`, `/events`, revision history, ingestion/import jobs, forecast lists/provenance/maps/cells, evaluations/revisions, metrics, model registry/promotions, promotion history/model-selection preview, persisted schedule settings/history/status, training/backtest jobs, cancellation, and JSON exports are available. No endpoint edits issued probabilities. All expensive API actions return a durable job ID. See the generated contract or the local API's `/docs` (interactive docs may need their own CDN assets; the application itself does not).
