# Catalogue sources and basemap

## USGS

[Official event service](https://earthquake.usgs.gov/fdsnws/event/1/) and [GeoJSON feeds](https://earthquake.usgs.gov/earthquakes/feed/v1.0/geojson.php), consulted 2026-09-29. The query service caps responses at 20,000 records. Imports use 30-day chunks, preflight counts, recursive subdivision at 19,000, and count-versus-payload verification. Inclusive service boundaries are filtered locally to half-open intervals. Requests have timeouts, bounded exponential retry, and a rate limit. Recent feeds supplement reconciliation queries; feed delivery alone never establishes complete scoring coverage.

USGS selects a preferred magnitude whose type may vary. `usgs_preferred_m4_v1` targets that magnitude >= 4.0; it is neither uniform Mj nor uniform Mw. The input threshold is 3.0. Data attribution: USGS Earthquake Hazards Program, public domain. A successful query establishes retrieval health, not physical-event catalogue completeness.

Source namespaces include query domain and input threshold so narrower retrieval cannot establish negative labels for a wider experiment. Absence from any query does not create a deletion. Explicit deletion revisions do. Origin, provider update, and local receipt timestamps remain separate. Late delivery of an older provider version does not supersede a newer one. Raw content is content-addressed and verified on reuse.

Known-ID reconciliation uses the official service's `eventid` query with `format=geojson` and `includedeleted=true`, independently of discovery magnitude, location, time and event-type filters. The [single-event GeoJSON format](https://earthquake.usgs.gov/earthquakes/feed/v1.0/geojson_detail.php) and event-service semantics were checked again on 2026-10-25. Each 30-day interval captures up to 10,000 preexisting IDs before retrieval, including events whose older revisions occupied that interval. Newly persisted feed IDs within that interval join the same bounded reconciliation set. IDs absent from valid discovery results receive individual requests. An exact matching identity and usable normalized revision are required; an alias mismatch, malformed response, HTTP error or absent event remains unresolved. Only an explicit valid deletion revision removes an event from selection.

Each job permits at most 100 physical known-ID request attempts, including retries, with a 120-second cumulative budget for that work. An outer asynchronous deadline covers both response headers and body reception; network inactivity timeouts alone would not bound a trickling response. Discovery requests have a 45-second total deadline and retain separate chunking/retry limits. Limits, overflows, unresolved IDs, failures and bounded samples are recorded; narrow the requested interval when reconciliation cannot finish within those limits. Requests and response bodies are retained as content-addressed artifacts, with receipt timestamps, response headers and an explicit completeness flag for interrupted bodies. An interval stays unknown while reconciliation is pending or incomplete. Completion requires valid discovery and resolution of every captured known ID, without an ID-read overflow. A feed alone cannot resolve an ID missing from the subsequent authoritative query.

Only one USGS attempt may run per source. A bounded, nonblocking PostgreSQL session lock covers retrieval without keeping a transaction open; competing attempts fail visibly for retry. Every write checks that the original database session still owns that lock inside the short source write transaction. A disconnected old attempt cannot append data or completion evidence after a successor, and cleanup physically discards the lock connection. Different sources remain independent. This prevents concurrent attempts from completing against stale known-ID sets or interleaving unfinished supplements with another attempt's complete receipt.

The 2026-10-25 live FDSN query (API 2.8.2) omitted `metadata.count` despite returning a valid feature array. Query responses may omit that field only when their array matches the independent count preflight. Present invalid or conflicting counts still fail; summary feeds still require their own count. The saved live-response fixture and bounded smoke evidence are documented in [verification](verification.md#2026-10-25-catalogue-correction-acceptance-t024).

Corrections to known IDs are retained even when their magnitude, location, origin time or event type leaves the experiment's selection. Eligibility is applied only after choosing the authoritative revision. Event type and source-policy exclusions are distinct from provider review status; model inputs, evaluation labels, map markers and event lists share that selection rule. Earlier snapshots retain their original revision IDs.

Coverage is evaluated as of the requested receipt-time cutoff. Each part of the target interval must have a successful authoritative retrieval/import as its latest attempt. A later partial or failed attempt makes its overlapping interval unknown until a subsequent successful attempt covers it. Earlier complete evidence remains available to earlier cutoffs. Feed deliveries and individual correction receipts are supplemental: they neither establish nor invalidate interval coverage. Equal-time contradictory attempts fail closed. This policy protects against combining a partly updated catalogue with an older coverage claim.

## JMA

[Official catalogue](https://www.data.jma.go.jp/eqev/data/bulletin/hypo_e.html), [96-byte record format](https://www.data.jma.go.jp/eqev/data/bulletin/data/format/hypfmt_e.html), and [usage terms](https://www.jma.go.jp/jma/en/copyright.html). The implementation was checked against the official `h2023.zip` download, not a converted JSON API. The one-line test fixture comes from that file (JMA attribution retained here).

Parser version 2 converts JST origin time to UTC and supports FORTRAN implied decimals, depth-slice integer fields, null depth and negative magnitude letter notation. Selection requires JMA agency J, natural-earthquake flags 1/2/5 and magnitude family J/D/d/V/v. Structurally valid U/I agency determinations, excluded event flags 3/4, and W/B/S magnitude families are recognized policy exclusions. Unknown codes, quality code 8 (unaccepted hypocentre), missing or malformed magnitude, invalid coordinates/timestamps and truncated records block complete coverage. Seconds and coordinate minutes cannot overflow into another time or degree. The JMA magnitude family is recorded exactly, not relabelled as uniform Mw.

Official U/I rows can omit JMA-specific subsidiary/precision fields; those blanks do not prevent an otherwise valid agency exclusion. Signed padded degree fields, including negative zero, are supported. Unknown nonblank codes and malformed core fields remain invalid. Full `h2023` verification selected 246,944 rows, safely excluded 103, and reported 9,973 rows with undetermined magnitudes as coverage blockers. That file therefore remains partial without additional trustworthy evidence; recognized exclusions do not turn it into a complete catalogue.

Create a JMA experiment with an explicit `catalogue_namespace` before importing. It names an isolated catalogue collection, uses 3–80 lowercase letters, digits, underscores or hyphens, and starts with a letter or digit. Experiments with the same collection and retrieval domain share a source; different collections cannot change one another's observations. Legacy experiments remain readable with their original hashes, but cannot accept new untracked local imports. Choose a new collection instead of attempting to adopt that history.

The official fixed-width format has **no stable event ID**. Identity is `file namespace:physical line number`, within its collection. The same file namespace is permanently tied to its raw content and line count. Different file namespaces in one collection cannot reuse identical content or declare overlapping coverage intervals; adjacent annual files are supported. A revised, reordered or inserted-line file requires a **new catalogue collection**. Automatic cross-file event matching is not claimed. Fixed-width and CSV imports cannot share a collection. Provide an uncompressed file of at most 32 MiB; the application does not extract ZIP archives.

Canonical CSV requires `provider_id,origin_time,longitude,latitude,magnitude,magnitude_type`. Optional columns are `depth_km,provider_updated,status,event_type`. Timestamps require a timezone; coordinates are decimal degrees and depth is km. Blank depth/update remain null; blank status defaults to `reviewed`, and blank event type defaults to `earthquake`. Status accepts `reviewed`, `automatic` or `deleted`; event type accepts `earthquake`, `explosion` or `non_earthquake`. Unknown values are coverage blockers. CSV IDs must be nonblank and have no surrounding whitespace. Headers, row widths and quoting are checked; malformed rows are not silently padded or truncated. Multipart `mapping` accepts a JSON object from source header names to canonical fields, for example `{"event_id":"provider_id","time":"origin_time"}`. Missing fields, duplicate headers or mappings, unknown destinations and destination collisions are rejected.

CSV corrections use stable provider IDs within a collection. Valid known-ID changes remain archived when origin time, location, magnitude or event type leaves the selection. Without provider update times, receipt order determines the latest distinct content. Exact file/declaration replays return the original receipt without creating a new revision or refreshing coverage. To represent an intentional return to an earlier value, provide fresh provider-version evidence or new file content; replaying an old file does not express a new correction.

Imports default to unknown coverage. `coverage_declared=true` is an explicit assertion that the file contains the complete catalogue for its completed, half-open interval. Only that declaration plus zero invalid/ambiguous rows establishes coverage. Recognized policy exclusions do not prevent it. Reports retain selected, policy-excluded and invalid counts, reason totals and up to 100 physical-line examples per category; valid excluded rows can still correct known events. Any parsed partial import invalidates older coverage over its interval. Structural or identity validation failures commit no catalogue changes.

Each committed import has an immutable manifest containing its source, file namespace, format/parser version, verified raw hash/artifact, physical line count, mapping, interval, declaration and ingestion receipt. Validation, revisions, receipt and manifest commit together under the source lock. Identical effective requests deduplicate; changed intervals or declarations are separate evidence. The API's optional `submission_id` allows an explicit retry of a failed job, while manifest identity still prevents duplicate committed imports. The import form supplies a fresh submission ID per click and resets its coverage declaration whenever the file or scope changes.

## Offline basemap

Natural Earth 1:50m land, release 5.1.2, clipped and simplified for the Japan region. [Public domain terms](https://www.naturalearthdata.com/about/terms-of-use/). Attribution: “Made with Natural Earth.” The local GeoJSON requires no runtime internet connection, tiles, fonts, or map API key. It is contextual cartography; forecast cells use the independent versioned EPSG:6933 domain.
