# Experiment protocol v1

## Target and domain

The target is a binary cell-window occurrence: at least one selected catalogue event at or above the experiment's target magnitude, initially 4.0. It does not predict shaking, damage, tsunami, or personal safety. The input threshold is initially 3.0. Provider, magnitude selection, geometry, thresholds, and evaluation policy are immutable experiment settings. Changes require a new experiment version.

The Japan-region envelope is `[122,156)` longitude and `[20,48)` latitude, including offshore and neighbouring regions. EPSG:6933 squares are 50,000 projected metres, clipped at the exact envelope; 3,953 cells are retained. Interior cells are about 2,500 km². Actual WGS84 ellipsoidal polygon areas are stored. Projected dimensions are not exact ground distances. IDs are projected integer column:row. Shared boundaries belong to the north/east cell (projection roundoff within 0.05 mm is snapped to the mathematical edge). The outer east/north edges are excluded. No post-event radius expansion is permitted.

## Timing and evidence

All stored times are aware UTC; display/scheduling uses Asia/Tokyo. A JST midnight starts at 15:00 UTC on the preceding date. Target windows are half-open `[start,end)` and exactly 24 hours. The v1 feature cutoff is exactly 30 minutes before the start. Scheduled next-day generation begins at 23:40 JST using the 23:30 cutoff; publication must finish before 00:00. A manual run starts 30 minutes after its cutoff, with the actual publication time recorded. A late scheduled run is marked missed, never backdated.

Prospective input snapshots select the latest provider revision *received by the cutoff*, then apply event eligibility and origin-time filters. A disqualifying correction never revives an older eligible revision. Provider update time orders out-of-order revision deliveries; receipt time controls availability. Model/preprocessing/calibration artifacts must exist before issue time, with training cutoff no later than input cutoff. Training labels never include the target/test period. Inputs require successful recent retrieval covering the preceding day through at least cutoff minus 30 minutes, and a nonfailed source. This is a declared latency allowance, not proof of catalogue completeness. Unknown target coverage never supplies negative labels.

- `prospective`: actual future publication and receipt-time-restricted inputs.
- `retrospective_revised`: historical study using versions downloaded/revised later. Issue time remains the real current publication time.
- `synthetic_demo`: artificial, fixed-seed data with explicitly historical dates.
- `replay_asof`: reserved and rejected in v1; historical fitted artifacts and availability evidence would be necessary.

Modes are kept separate in API filters and comparisons. Forecast runs, individual probabilities, classifications, model metadata, snapshots, and evaluations are database protected append-only archives. Atomic publication verifies the exact retained-cell count and domain, then seals the run against later insertions.

## Chronological model development

Defaults: 180 fitting days, 30 tuning days, 30 calibration days, then 7 testing days; 90 warmup days are required. The CLI accepts larger partitions (e.g. 730/90/90/180) subject to a four-million-cell-day bound. Coarsen a *new* grid or reduce partitions if needed. Every cell on a date stays in the same partition. Full target windows are contained within one partition, and the final target interval ends before the forecast cutoff. No random split, random early stopping, negative sampling, or class weighting is used.

Feature rows only use earlier eligible origin times under the declared revised-catalogue research policy. Generated background features use expanding earlier counts, never a baseline fitted on later dates. Feature Parquet batches and partition manifests are immutable. Model parameter selection uses the tuning block; sigmoid calibration uses the separate later calibration block. Backtest folds refit before each later testing block. Outcomes learned from an earlier test period make further work exploratory; saved forecasts remain fixed and later candidates need new evaluation periods.

## Scores and revision policy

Only complete retrieved target windows supply labels. No covered source interval means status `awaiting_data`, zero eligible samples, all cells missing, and undefined scores. Available evaluations remain provisional: neither USGS review status nor elapsed D+3/D+7/D+30 alone guarantees completeness or finality. Daily reconciliation covers the last 31 days and rescoring appends changed observation versions, retaining old results.

Saved display bands initially use green <1%, yellow ≥1% and <5%, red ≥5%. Classification uses that frozen red threshold. The headline “Affected cells identified” is `TP/(TP+FN)`; precision is `TP/(TP+FP)`. Undefined denominators display N/A. Red coverage is the fraction of eligible area-time marked red. Brier score is mean squared probability error. Log loss uses numeric clipping at 1e-12 while preserving raw probabilities and counts of confident misses. Average precision is reported only with both classes and at least five positive cells.

Aggregate sums/counts are pooled; incompatible daily percentages are never averaged. Brier skill is `1 - candidate Brier / reference Brier` on identical experiment/window/mode/observation revision/eligible-cell pairs. Exclusions are reported. Paired moving seven-day blocks, seed 2026, 1,000 resamples, require at least 28 consecutive matched days. No winner is declared for short or interrupted records. Calibration displays fixed bins and their counts. Synthetic scores are software evidence, not scientific forecasting evidence.

Reference policy `earliest-compatible-historical-rate-v1` chooses the earliest archived compatible `historical_rate` forecast for each exact `[start,end)` window, ordered by `forecast.created_at`, then model ID, then forecast ID. Scores never determine this order. Compatibility requires the same experiment, mode, grid hash, canonical observation revision set, and actual eligible cell IDs and binary labels. Evaluation version numbers need not match across forecasts. Evidence must belong to the experiment's source and grid; unique eligible cells plus the missing count must account for the entire grid. Equal sample counts alone do not establish compatibility.

Each window reports its chosen reference model, forecast, and evaluation IDs/version, or explicit exclusion reasons. A baseline may reference itself, which is marked explicitly. Different rolling windows may use different archived reference models; the report lists and counts those versions. Unevaluated and awaiting-data forecasts remain in total/excluded window accounting. The score series contains only trusted evaluated forecasts, including validated zero-observation rows; invalid evaluations retain their identities and reasons in the decisions. Derived history scores are recomputed from stored sums/counts. Comparison scores use only the matched cohort; period scores from all valid evaluated windows remain separately identified.

Forecast accounting separates scoreable, unevaluated, unavailable-evaluation and invalid-evidence windows. `total_cell_windows` counts the immutable grid for every forecast, `observed_cell_windows` counts valid scored observations, and `unscored_cell_windows` is their difference. `missing_cell_windows` is narrower: it counts missing cells explicitly established by trusted evaluations, so it excludes unevaluated and invalid evidence. `paired_cell_windows` and paired missing counts describe the exact comparison cohort. A pure caller without grid-size evidence receives null total/unscored counts and an explicit unknown-size forecast count; the database report always supplies the immutable grid. Missing or unscored cells never become negatives or enter performance denominators. Primary exclusion-reason totals count each excluded forecast once; the full reason totals may overlap.

Uncertainty uses the same pooled cell-window estimand as the comparison. For matched window `d`, retain `difference_sum[d] = candidate.brier_sum[d] - reference.brier_sum[d]` and its common eligible count `n[d]`. The point estimate is `sum(difference_sum) / sum(n)`. Each moving-block resample selects seven consecutive paired windows and carries both sums and counts together, then computes that ratio again; it does not average daily percentages. Eligibility requires finite evidence, positive matched counts, unique consecutive 24-hour windows and at least 28 matched days. Gaps, duplicate/manual overlaps, other durations and short records have explicit unavailable reasons. No pairs and zero reference Brier are distinct reasons for undefined Brier skill. These seeded empirical intervals remain experimental and do not establish a winning model.

## Report scope and export identity

`GET /metrics` and `GET /exports/metrics` share the same report builder. Both require an experiment and a supported mode. Omitted scope defaults to 30 days; a positive `days` value ends at the latest evaluated target window that has already ended. Future forecasts and unevaluated issuances cannot move that anchor. If no such window exists, the resolved bounds are null and the report explains `no_completed_evaluated_window`. Unevaluated and awaiting forecasts inside an established scope remain in its decisions and availability counts.

`days=0` means the whole archived experiment/mode, including future or unevaluated forecasts; its bounds cover the earliest start through the latest end. Explicit `start` and `end` must both carry timezone offsets, be ordered, and cannot be combined with `days`. All bounds are normalized to UTC. A forecast is included only when its entire `[start,end)` target window is contained in the requested interval. A JST date selection converts local midnight boundaries to UTC, with the upper boundary at midnight after the last selected date. Empty explicit ranges retain their requested bounds.

Requests are bounded to 3,650 days, 2,000 forecasts, 10,000 grid cells and 1,000,000 combined forecast/evaluation cell evidence rows. Oversized reports return an actionable error to narrow the range; forecasts are never silently truncated. Database statements have a 15-second timeout; query cancellation returns HTTP 503 with narrowing/retry guidance. The report echoes its requested/resolved scope, limits, experiment configuration and grid identities, evaluation-selection policy and comparison provenance.

Evidence reads use one read-only repeatable-read transaction, so bounds, forecasts and evaluation choices see a stable database view. PostgreSQL defines that snapshot at the first non-control statement; it is not a historical receipt-time cutoff. `generated_at` records report generation time. See the [PostgreSQL isolation semantics](https://www.postgresql.org/docs/17/transaction-iso.html#XACT-REPEATABLE-READ) and [SQLAlchemy transaction configuration](https://docs.sqlalchemy.org/en/20/orm/session_transaction.html#setting-transaction-isolation-levels-dbapi-autocommit).

`report_id` hashes the normalized report content, excluding its own identifier and generation time. A caller may provide `expected_report_id` to the export endpoint; a changed report returns HTTP 409 instead of silently exporting different observation versions. To preserve the exact report already displayed, a client can download that retained JSON directly. A content identifier detects changes; it is not a server-side archive of report payloads.
